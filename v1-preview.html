SAFETY GATE

Why receive and send are still disabled

The Cashu SDK expects the application to manage proof state and persistence. Receiving can swap proofs at the mint; without durable storage, atomic state transitions, duplicate-token protection and crash recovery, funds could be lost. The project must implement and test these safeguards before enabling receive, send or Lightning operations.

REMAINING MILESTONES

What must happen before a real-money release

1. Integrate encrypted storage with robust schema migrations and backup/recovery.
2. Define key custody, password UX, device compromise and recovery threat models.
3. Implement atomic proof lifecycle, in-flight locks, crash recovery and duplicate-token protection.
4. Build receive/send and Lightning flows against isolated test mints.
5. Add end-to-end, failure/replay and protocol tests; audit dependencies and obtain independent security review.
